## 0. 本次修订说明

本次基于 V0.1 需求文档进行规则修订，重点解决「每次点击正确数字后是否需要持续标记」的问题。

### 0.1 修订背景

在舒尔特方格训练中，用户需要在完整的随机数字方格中持续进行视觉搜索。如果每点击一个数字后，都将该数字隐藏、置灰、移除或长期标记为完成态，后续可搜索目标会逐渐减少，训练难度会随进度降低，最终成绩也会变得不适合直接和标准成绩表对照。

因此，本版本明确区分：

1. **标准训练模式**：用于正式训练和成绩评级，点击正确数字后不做持续性完成标记。
2. **辅助练习模式**：用于儿童、新手或教学场景，可以显示已完成标记，但成绩仅作为练习参考，不参与标准等级对照。

### 0.2 本次主要变更

| 变更项     | V0.1 描述         | V0.2 修订                       |
|---------|-----------------|-------------------------------|
| 正确点击反馈  | 当前数字标记为已完成      | 默认仅短暂反馈，不做持续标记                |
| 已点击数字显示 | 已点击数字可以变淡或显示完成态 | 标准模式不隐藏、不置灰、不移除；辅助模式才允许变淡或完成态 |
| 成绩评级    | 基于规格、年龄段、完成时间   | 仅标准模式成绩参与正式评级；辅助模式成绩仅供练习参考    |
| 业务状态    | 未区分反馈模式         | 新增 MarkMode，用于区分标准与辅助反馈       |
| 验收标准    | 未验证是否破坏训练难度     | 新增标准模式下不持续标记的验收要求             |

### 0.3 V0.3 本次新增说明

本次在 V0.2 的标准训练规则基础上，新增「设置入口」与「AI 增强报告」能力。

新增目标不是让 AI 成为训练流程的前置依赖，而是让用户在完成训练后，可以选择通过自己配置的 AI 服务对训练结果进行分析，获得更具体的增强训练建议。

本次主要变更：

| 变更项   | V0.2 状态 | V0.3 修订                             |
|-------|---------|-------------------------------------|
| 设置入口  | 未明确设置页  | 首页或训练配置页新增设置入口                      |
| AI 配置 | 未包含     | 设置页支持配置 AI API Key、Base URL、模型名称等信息 |
| 训练报告  | 仅展示结果   | 新增本次训练报告，展示时间、错误、规格、年龄段、模式等结构化信息    |
| AI 分析 | 未包含     | 结果页支持触发 AI 分析，生成表现解读与增强训练建议         |
| 隐私安全  | 未涉及     | 明确 API Key 本地加密保存、用户主动触发才发送训练数据     |
| 降级策略  | 未涉及     | 未配置 AI 时仍可正常训练和查看基础报告               |

## 1. 产品背景

舒尔特方格是一种常见的注意力集中训练、视觉搜索训练和反应速度训练工具。用户需要在随机排列的完整数字方格中，从数字 1 开始，按照递增顺序依次点击所有数字。标准训练过程中，已点击数字不应被隐藏、移除或长期标记，从而保证用户始终在完整方格中进行视觉搜索。

本 App 当前阶段定位为一个轻量级训练工具，不做复杂社区、排行榜、账号系统或游戏化成长系统，重点是让用户快速开始一次训练，并在完成后获得清晰的成绩反馈。

在 V0.3 中，结果反馈从单纯展示成绩，扩展为「基础训练报告 + 可选 AI 增强建议」。用户可以在设置中配置自己的 AI API Key 与 Base URL，在完成训练后主动发起 AI 分析，获得更个性化的训练建议。

---

## 2. 产品定位

「舒尔特方格训练」是一款用于提升注意力集中、视觉搜索速度和反应能力的手机训练工具。

核心特点：

1. 简洁、专注、低干扰。
2. 操作路径短，用户打开后可以快速开始训练。
3. 通过不同方格规格和年龄段，提供适配不同用户的成绩参考。
4. 当前版本只做训练闭环，不做复杂数据沉淀。
5. 标准训练模式下保持完整方格可见，避免通过持续标记降低后续搜索难度。
6. 提供设置入口，允许用户配置自己的 AI 服务参数。
7. 训练完成后提供基础报告，并可选择使用 AI 生成增强训练建议。

## 4. 当前版本目标

### 4.1 核心目标

让用户能够完成一次完整的舒尔特方格训练流程：

选择训练规格和年龄段 → 开始训练 → 按顺序点击数字 → 完成后查看成绩结果与训练报告 → 可选使用 AI 分析增强训练建议。

### 4.2 MVP 成功标准

1. 用户可以选择方格规格。
2. 用户可以选择年龄段。
3. 系统可以生成随机数字方格。
4. 用户必须按 1 到 N 的顺序点击。
5. 系统记录完成时间。
6. 系统记录错误次数。
7. 完成后展示成绩等级。
8. 用户可以重新开始训练。
9. 标准模式下，正确点击后仅提供短暂反馈，不隐藏、不移除、不持续置灰已点击数字。
10. 用户可以从首页或训练配置页进入设置页。
11. 用户可以在设置页配置 AI API Key、Base URL 和模型名称。
12. 完成训练后，系统可以生成本次训练基础报告。
13. 当 AI 配置有效时，用户可以主动触发 AI 分析，获取增强训练建议。

## 7. 页面需求

## 7.1 首页 / 训练配置页

### 页面目标

让用户在开始前完成基础训练配置。

### 页面内容

1. App 名称：舒尔特方格训练。
2. 简短说明：训练专注力、视觉搜索和反应速度。
3. 方格规格选择：
   - 3x3：入门
   - 4x4：初级
   - 5x5：中级
   - 7x7：高级
4. 年龄段选择：
   - 3~5岁
   - 6~10岁
   - 11~17岁
   - 18岁以上
5. 主按钮：开始训练。
6. 设置入口：建议放在右上角图标按钮，或首页底部次级入口。

### 交互规则

1. 默认选中 5x5 和 18岁以上。
2. 用户必须选择方格规格和年龄段后才能开始。
3. 点击「开始训练」后进入训练页。
4. 当前版本不需要复杂引导页。
5. 默认进入标准训练模式。
6. MVP 阶段可以不暴露「辅助练习模式」入口；如需要支持儿童或新手场景，可在后续设置项中增加。
7. 点击设置入口后进入设置页。
8. 设置入口不应干扰用户快速开始训练，视觉权重低于「开始训练」按钮。

---

## 7.2 训练页

### 页面目标

让用户专注完成一次舒尔特方格训练。

### 页面内容

1. 顶部状态区：
   - 当前目标数字，例如：请点击 1
   - 当前计时，例如：00:12.35
   - 错误次数，例如：错误 2 次
2. 中间训练方格：
   - 根据规格显示 3x3、4x4、5x5 或 7x7。
   - 数字随机排列。
3. 底部操作区：
   - 重新开始
   - 退出训练 / 返回

### 交互规则

1. 进入训练页后，系统生成随机数字方格。
2. 用户点击「开始训练」后直接开始计时。
3. 用户点击正确数字：
   - 下一个目标数字递增。
   - 标准模式下不隐藏、不移除、不持续置灰该数字。
   - 可给出 100ms～200ms 的短暂视觉反馈，例如轻微缩放、点击波纹或瞬时高亮。
   - 短暂反馈结束后，数字恢复普通显示状态。
4. 用户点击错误数字：
   - 错误次数 +1。
   - 当前目标数字不变。
   - 可给出轻微震动或红色闪烁提示。
   - 错误反馈也应保持轻量，避免影响继续搜索。
5. 当用户点击完最后一个数字后：
   - 停止计时。
   - 进入结果页或弹出结果弹窗。

---

## 7.3 结果页 / 结果弹窗

### 页面目标

清晰展示本次训练结果，并引导用户再次训练。

### 页面内容

1. 本次完成时间。
2. 错误次数。
3. 方格规格。
4. 年龄段。
5. 成绩等级：
   - 优
   - 良
   - 及格
   - 未达标
6. 是否为标准成绩：
   - 标准模式：展示正式等级。
   - 辅助模式：展示“练习参考，不参与标准评级”。
7. 基础训练报告：
   - 表现摘要
   - 本次训练参数
   - 完成时间与评级
   - 错误次数
   - 训练模式
8. AI 增强分析入口：
   - 已配置 AI：显示「AI 分析」按钮。
   - 未配置 AI：显示「配置 AI 后解锁分析建议」提示。
9. 操作按钮：
   - AI 分析
   - 再来一次
   - 返回首页
   - 进入设置

### 交互规则

1. 点击「再来一次」：
   - 保持当前方格规格和年龄段。
   - 重新生成随机数字。
   - 开始新一轮训练。
2. 点击「返回首页」：
   - 回到训练配置页。
3. 当前版本不强制保存历史记录。
4. 点击「AI 分析」：
   - 如果 AI 配置完整，基于本次训练报告生成分析建议。
   - 如果未配置 API Key 或 Base URL，引导用户进入设置页。
   - 分析过程需要展示 loading 状态。
   - 分析失败时保留基础报告，并提示用户检查配置或网络。

## 7.4 设置页

### 页面目标

让用户管理训练偏好和 AI 服务配置，支持后续通过 AI 对训练报告进行分析。

### 页面入口

1. 首页 / 训练配置页右上角设置图标。
2. 结果页中「进入设置」按钮。
3. AI 分析不可用时的配置引导入口。

### 页面内容

#### 7.4.1 训练设置

1. 默认方格规格：3x3 / 4x4 / 5x5 / 7x7。
2. 默认年龄段：3~5岁 / 6~10岁 / 11~17岁 / 18岁以上。
3. 点击反馈模式：
   - 标准模式：仅短暂反馈，参与正式评级。
   - 辅助模式：显示已点击标记，仅作为练习参考。
4. 震动反馈开关：开启 / 关闭。

#### 7.4.2 AI 设置

1. AI 功能开关：开启 / 关闭。
2. API Key：用户自行填写。
3. Base URL：用户自行填写，建议兼容 OpenAI 风格接口。
4. 模型名称：用户自行填写，例如 `your-model-name`，具体名称以用户所配置的 AI 服务为准。
5. 请求超时时间：可使用默认值，例如 30 秒。
6. 测试连接：验证 Base URL、API Key、模型是否可用。
7. 清除配置：删除本地保存的 API Key 和 AI 配置。

### 交互规则

1. API Key 输入框默认密文展示。
2. 用户可以点击图标临时显示 / 隐藏 API Key。
3. Base URL 不能为空；如果为空，AI 分析不可用。
4. API Key 不能为空；如果为空，AI 分析不可用。
5. 模型名称为空时，可以使用默认模型名称，但需要在 UI 中明确展示。
6. 点击「测试连接」后：
   - 成功：提示连接可用。
   - 失败：展示可理解的错误信息，例如 API Key 无效、Base URL 不可访问、模型不存在、网络超时。
7. 设置保存后立即生效。
8. AI 设置只影响报告分析，不影响基础训练流程。

## 7.5 训练报告 / AI 分析页

### 页面目标

在用户完成训练后，先提供本地可生成的基础报告，再允许用户主动调用 AI 生成增强训练建议。

### 页面内容

#### 7.5.1 基础训练报告

基础报告不依赖 AI，必须本地生成。

报告字段：

| 字段     | 说明                      |
|--------|-------------------------|
| 方格规格   | 3x3 / 4x4 / 5x5 / 7x7   |
| 年龄段    | 用户当前选择的年龄段              |
| 完成时间   | 本局完成耗时                  |
| 错误次数   | 本局错误点击次数                |
| 成绩等级   | 优 / 良 / 及格 / 未达标 / 练习参考 |
| 训练模式   | 标准模式 / 辅助练习模式           |
| 是否正式成绩 | 标准模式为是，辅助模式为否           |
| 完成时间对照 | 展示当前成绩距离上一级目标的差距        |

#### 7.5.2 AI 增强分析

AI 分析内容建议包括：

1. 本次表现总结。
2. 完成时间与当前年龄段参考标准的对比。
3. 错误次数对训练质量的影响。
4. 是否建议降低 / 保持 / 提升方格规格。
5. 下一次训练目标，例如：
   - 5x5 保持标准模式，目标从 29 秒提升到 27 秒以内。
   - 连续 3 次错误次数控制在 1 次以内后，再尝试 7x7。
6. 注意力训练建议，例如：
   - 训练前保持固定坐姿和视距。
   - 不要用手指提前遮挡或扫格。
   - 先保持准确率，再提升速度。
7. 风险提示：AI 建议仅作为训练参考，不构成医学、心理诊断或治疗建议。

### 交互规则

1. 用户点击「AI 分析」后才发起网络请求。
2. 发起请求前，应明确本次将发送训练数据用于生成建议。
3. 请求过程中展示加载状态，避免重复点击。
4. 请求成功后展示结构化建议。
5. 请求失败后展示失败原因，并保留基础报告。
6. 用户可以重新发起分析。
7. 用户可以复制 AI 建议文本。
8. 当前版本不自动保存 AI 分析内容，除非后续版本增加历史记录。

## 8. 训练规则

### 8.1 方格规格

| 规格  | 数字范围 | 难度 |
|-----|-----:|----|
| 3x3 |  1~9 | 入门 |
| 4x4 | 1~16 | 初级 |
| 5x5 | 1~25 | 中级 |
| 7x7 | 1~49 | 高级 |

### 8.2 数字生成规则

1. 根据方格规格生成连续数字。
2. 例如 5x5 生成 1 到 25。
3. 每局开始时随机打乱数字顺序。
4. 同一局内数字不重复、不遗漏。

### 8.3 点击规则

1. 用户必须从 1 开始点击。
2. 正确点击后，目标数字 +1。
3. 错误点击不推进进度。
4. 错误点击需要累计错误次数。
5. 全部数字点击完成后，训练结束。

### 8.4 点击反馈与标记规则

#### 8.4.1 标准训练模式

标准训练模式是默认模式，用于正式训练和成绩评级。

规则如下：

1. 正确点击后，数字不隐藏。
2. 正确点击后，数字不从方格中移除。
3. 正确点击后，数字不持续置灰、不长期显示勾选态。
4. 正确点击后，只允许短暂反馈，建议时长 100ms～200ms。
5. 短暂反馈结束后，格子恢复普通状态。
6. 用户始终在完整数字方格中搜索下一个目标。
7. 顶部可以显示当前目标数字，例如“请点击 13”。

设计原因：

```text
如果已点击数字被持续标记，后续剩余数字会越来越少，搜索难度会逐渐降低，完成时间会被辅助机制影响。
```

#### 8.4.2 辅助练习模式

辅助练习模式用于儿童、新手或教学场景，不作为默认模式。

允许行为：

1. 已点击数字可以轻微变淡。
2. 已点击数字可以显示完成态。
3. 已点击数字可以降低视觉权重，但不建议完全隐藏。
4. 结果页必须提示：本次使用辅助标记，成绩仅供练习参考。

限制：

1. 辅助练习模式成绩不参与标准等级对照。
2. 辅助练习模式不应与标准成绩混合展示。
3. 如果后续增加历史记录，需要记录本局使用的 MarkMode。

#### 8.4.3 推荐默认策略

MVP 默认采用：

```kotlin
enum class MarkMode {
    BriefFeedbackOnly, // 标准模式：仅短暂反馈，参与正式评级
    AssistedMarking    // 辅助模式：持续标记，仅练习参考
}
```

默认值：

```kotlin
MarkMode.BriefFeedbackOnly
```

### 8.5 计时规则

1. 点击「开始训练」后开始计时。
2. 点击最后一个正确数字后停止计时。
3. 计时精度建议显示到 0.01 秒。
4. 成绩计算使用秒作为基础单位。

## 9. 成绩评分规则

### 9.1 评分维度

当前版本成绩等级主要基于完成时间，但只有标准训练模式成绩参与正式评级。

错误次数在当前版本中作为辅助展示指标，不直接影响等级。后续版本可以考虑加入惩罚机制，例如每次错误增加 1 秒或降低评级。

如果本局使用辅助练习模式，由于已点击数字的持续标记会降低后续搜索难度，结果页可以展示完成时间和错误次数，但不直接套用标准成绩等级。

### 9.2 成绩等级

| 等级  | 说明              |
|-----|-----------------|
| 优   | 完成速度非常快         |
| 良   | 完成速度较好          |
| 及格  | 达到基础完成标准        |
| 未达标 | 超过当前规格和年龄段的及格时间 |

### 9.3 评分标准说明

当前评分标准按照以下维度组合判断：

```text
方格规格 + 年龄段 + 完成时间 + 标准训练模式 = 成绩等级
```

其中，标准训练模式要求：

```text
MarkMode = BriefFeedbackOnly
```

辅助练习模式下：

```text
MarkMode = AssistedMarking → 成绩仅供练习参考，不参与标准等级对照
```

例如：

```text
规格：5x5
年龄段：18岁以上
完成时间：18秒
结果：优
```

```text
规格：5x5
年龄段：18岁以上
完成时间：23秒
结果：良
```

```text
规格：5x5
年龄段：18岁以上
完成时间：29秒
结果：及格
```

```text
规格：5x5
年龄段：18岁以上
完成时间：35秒
结果：未达标
```

## 10. 训练报告与 AI 分析规则

### 10.1 AI 能力定位

AI 分析是训练后的可选增强能力，不是完成训练的必要条件。

| 状态         | 产品行为                         |
|------------|------------------------------|
| 未配置 AI     | 可正常训练，可查看基础报告，AI 分析按钮置灰或引导配置 |
| 已配置 AI     | 可在结果页主动触发 AI 分析              |
| AI 请求失败    | 保留基础报告，展示失败原因，不影响训练结果        |
| 用户关闭 AI 功能 | 不展示或弱化 AI 分析入口               |

### 10.2 AI 分析输入数据

AI 分析只需要发送和训练结果相关的最小数据集。

建议输入字段：

```json
{
  "appName": "舒尔特方格训练",
  "gridSize": 5,
  "ageGroup": "AGE_18_PLUS",
  "elapsedTimeSeconds": 29.35,
  "errorCount": 2,
  "scoreLevel": "PASS",
  "markMode": "BriefFeedbackOnly",
  "isOfficialScore": true,
  "scoreStandard": {
    "excellentSeconds": 20,
    "goodSecondsRange": "21-25",
    "passSeconds": 30
  }
}
```

不建议发送：

1. 用户姓名。
2. 手机号、邮箱等个人身份信息。
3. 精确定位。
4. 与训练无关的设备隐私数据。
5. 未经用户确认的长期历史数据。

### 10.3 AI 分析输出结构

AI 返回内容建议整理为固定结构，便于 UI 展示：

```kotlin
data class AiTrainingAdvice(
    val summary: String,
    val performanceLevel: String,
    val timeAnalysis: String,
    val errorAnalysis: String,
    val nextTrainingGoal: String,
    val recommendedGridSize: Int,
    val recommendedPracticeMode: MarkMode,
    val suggestions: List<String>,
    val disclaimer: String
)
```

建议 UI 展示结构：

1. 总结：一句话说明本次表现。
2. 时间表现：解释完成时间处于什么水平。
3. 错误表现：解释错误次数是否影响训练质量。
4. 下一次目标：给出具体、可执行目标。
5. 训练建议：列出 3~5 条建议。
6. 提醒：AI 建议仅供训练参考。

### 10.4 Prompt 设计建议

应用内部可将基础报告组装为 Prompt，要求 AI 输出结构化建议。

示例：

```text
你是一个专注力训练助手。请根据以下舒尔特方格训练报告，给出简洁、具体、可执行的训练建议。

要求：
1. 不要做医学诊断。
2. 不要夸大训练效果。
3. 结合方格规格、年龄段、完成时间、错误次数和训练模式分析。
4. 给出下一次训练目标。
5. 给出 3~5 条增强训练建议。
6. 使用中文输出。

训练报告：
- 方格规格：5x5
- 年龄段：18岁以上
- 完成时间：29.35 秒
- 错误次数：2
- 成绩等级：及格
- 训练模式：标准模式
- 是否正式成绩：是
```

### 10.5 AI 请求规则

1. 请求必须由用户主动触发。
2. 请求前应确保 API Key、Base URL、模型名称有效。
3. Base URL 建议使用 HTTPS。
4. 请求超时时间建议默认 30 秒。
5. 请求失败时不应清空基础报告。
6. 不应在日志中打印 API Key。
7. 不应把 API Key 上传到非用户配置的服务端。
8. 如果 Base URL 是用户自定义地址，需要提示用户确认服务可信。

### 10.6 AI 配置安全规则

| 项目         | 规则                                     |
|------------|----------------------------------------|
| API Key 存储 | 本地加密保存，Android 建议使用 Keystore 或平台安全存储方案 |
| API Key 展示 | 默认密文展示，用户主动点击才临时显示                     |
| API Key 日志 | 禁止输出到日志、崩溃报告、埋点                        |
| Base URL   | 用户可编辑，建议校验 URL 格式                      |
| 请求内容       | 仅发送训练报告必要字段                            |
| 用户确认       | 首次 AI 分析前提示数据将发送到用户配置的 AI 服务           |
| 清除配置       | 设置页提供一键清除 AI 配置能力                      |

### 10.7 AI 分析边界

AI 只能提供训练建议，不应输出以下内容：

1. 医学诊断。
2. 心理疾病判断。
3. 治疗方案。
4. 对儿童能力的绝对评价。
5. 夸大舒尔特方格训练效果的结论。

推荐免责声明：

```text
AI 建议仅基于本次训练数据生成，用于训练参考，不构成医学、心理诊断或治疗建议。
```

## 12. UI 设计原则

### 12.1 整体风格

1. 简洁。
2. 专注。
3. 工具型。
4. 低干扰。
5. 不过度游戏化。

### 12.2 视觉建议

1. 背景使用浅色或低饱和色。
2. 方格数字清晰、对比度高。
3. 当前目标数字需要突出。
4. 正确点击反馈轻量化。
5. 错误点击反馈明确但不刺眼。
6. 结果页突出完成时间和等级。

### 12.3 方格设计

1. 每个格子需要有足够点击面积。
2. 7x7 模式下需要特别注意数字可读性。
3. 方格间距不宜过大，避免浪费屏幕空间。
4. 数字居中显示。
5. 标准模式下已点击数字不应持续变淡或显示完成态。
6. 辅助模式下可以轻微降低已点击数字的视觉权重，但结果必须标记为练习参考。

### 12.4 设置页设计

1. 设置页应保持工具型设计，不做复杂账号中心。
2. AI 设置应单独成组，避免与训练基础设置混在一起。
3. API Key 输入框默认隐藏内容。
4. Base URL 输入框需要展示示例格式。
5. 「测试连接」和「清除配置」需要有明确反馈。
6. AI 功能说明应清楚表达：使用用户自己的 API 服务，应用不提供默认托管 Key。

### 12.5 AI 报告设计

1. 基础报告和 AI 建议需要视觉区分。
2. 基础报告永远可见，AI 建议是增强内容。
3. AI 分析按钮需要展示可用 / 不可用状态。
4. AI 分析 loading 时禁止重复提交。
5. 分析失败时不应遮挡基础结果。
6. 建议内容应简洁、分段清晰，避免大段不可读文本。

## 13. 异常与边界场景

| 场景                    | 处理方式                           |
|-----------------------|--------------------------------|
| 用户点击错误数字              | 错误次数 +1，目标数字不变                 |
| 用户重复点击已完成数字           | 视为错误点击；标准模式下不会通过完成态提示该数字已点击    |
| 用户中途退出                | 弹出确认或直接返回，当前版本不保存              |
| 用户重新开始                | 重新生成数字并重置计时、错误次数               |
| 7x7 屏幕显示过密            | 自动调整字号和格子间距                    |
| App 切到后台              | MVP 可暂停计时或继续计时，建议暂停计时          |
| 标准模式下短暂反馈动画未结束又点击下一数字 | 仍按 nextTarget 校验；动画不影响业务状态     |
| 辅助模式下完成训练             | 结果页展示练习参考提示，不展示正式等级或不套用标准评级    |
| 未配置 AI 时点击 AI 分析      | 引导用户进入设置页配置 API Key 和 Base URL |
| API Key 错误            | 展示认证失败提示，不影响基础报告               |
| Base URL 不可访问         | 展示网络或地址错误提示                    |
| AI 请求超时               | 停止 loading，提示稍后重试              |
| AI 返回内容为空             | 展示分析失败提示，保留基础报告                |
| 用户关闭 AI 功能            | 结果页隐藏或弱化 AI 分析入口               |
| 用户清除 AI 配置            | 删除本地 API Key、Base URL、模型名称等配置  |
| 横竖屏切换                 | 当前版本建议锁定竖屏                     |

## 14. 非功能需求

### 14.1 性能要求

1. 页面切换流畅。
2. 点击反馈无明显延迟。
3. 计时显示稳定。
4. 生成方格应瞬时完成。

### 14.2 可用性要求

1. 用户 3 步内可以开始训练。
2. 训练页不能有过多干扰元素。
3. 结果反馈必须清晰易懂。
4. 儿童用户也能理解基础操作。
5. 标准模式下不能通过持续标记让后续数字搜索变得越来越简单。

### 14.3 可访问性要求

1. 数字字号足够清晰。
2. 颜色不能只依赖红绿区分。
3. 点击区域不宜过小。
4. 结果等级需要文字说明，不仅用颜色表达。


### 14.4 AI 与网络要求

1. AI 分析请求不应阻塞基础训练结果展示。
2. AI 请求失败不能影响用户重新开始训练。
3. AI 请求期间需要支持取消或返回。
4. 网络错误信息需要用户可理解，不能只展示原始异常堆栈。
5. 请求超时、认证失败、模型不存在、服务不可用需要分别处理。

### 14.5 安全与隐私要求

1. API Key 必须本地加密保存。
2. API Key 不允许进入普通日志、崩溃日志或埋点参数。
3. AI 分析只发送必要训练数据。
4. 首次 AI 分析前需要提示用户数据会发送到其配置的 AI 服务。
5. 应提供清除 AI 配置的入口。
6. AI 建议需要带有非诊断声明。

## 18. MVP 验收标准

### 18.1 配置页验收

- 用户可以看到 App 名称。
- 用户可以选择方格规格。
- 用户可以选择年龄段。
- 点击开始后进入训练页。

### 18.2 训练页验收

- 系统可以正确生成随机数字。
- 数字数量与规格一致。
- 用户必须按顺序点击。
- 正确点击后目标数字递增。
- 标准模式下，正确点击后不隐藏、不移除、不持续置灰已点击数字。
- 正确点击后只出现短暂反馈，反馈结束后恢复普通显示。
- 错误点击会累计错误次数。
- 计时正常运行。
- 全部点击完成后自动结束。

### 18.3 结果页验收

- 展示完成时间。
- 展示错误次数。
- 展示方格规格。
- 展示年龄段。
- 标准模式下展示正式成绩等级。
- 辅助模式下展示练习参考提示，不混用标准评级。
- 支持再来一次。
- 支持返回首页。


### 18.4 设置页验收

- 用户可以从首页 / 配置页进入设置页。
- 用户可以配置 API Key。
- 用户可以配置 Base URL。
- 用户可以配置模型名称。
- API Key 默认密文显示。
- 用户可以测试 AI 连接。
- 用户可以清除 AI 配置。
- 未配置 AI 不影响基础训练流程。

### 18.5 训练报告与 AI 分析验收

- 完成训练后展示基础训练报告。
- 基础报告不依赖 AI。
- 已配置 AI 时，可以点击「AI 分析」。
- 未配置 AI 时，点击 AI 分析入口会引导进入设置页。
- AI 分析请求期间展示 loading 状态。
- AI 分析成功后展示总结、时间分析、错误分析和训练建议。
- AI 分析失败后展示错误提示，并保留基础报告。
- AI 建议中必须包含“仅供训练参考，不构成医学或心理诊断”的提示。

## 19. 初版结论

当前项目的第一阶段应优先完成一个极简但完整的训练闭环：

```text
配置训练参数 → 开始训练 → 完整方格内顺序点击数字 → 记录时间和错误 → 展示成绩与基础报告 → 可选 AI 分析 → 重新训练
```

这个版本不追求功能复杂，而是要先验证核心体验是否顺畅：用户是否能快速进入训练、训练过程是否专注、结果反馈是否清晰，以及标准模式下是否保持完整方格搜索，不通过持续标记降低训练难度。后续再围绕历史记录、训练计划、数据分析、辅助练习模式、多模式训练以及基于多次训练数据的 AI 趋势建议逐步扩展。
