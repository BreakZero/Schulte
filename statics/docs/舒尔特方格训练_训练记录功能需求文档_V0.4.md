# 「舒尔特方格训练」训练记录功能需求文档 V0.4

> 项目名称：舒尔特方格训练  
> 当前版本：V0.4 / 训练记录与进步反馈版本  
> 产品类型：专注力训练工具型 App  
> 平台：手机客户端 App，优先移动端竖屏场景  
> 版本重点：训练记录、进步对比、总结优化、训练意愿提升  
> 设计原则：本地优先、轻量记录、低干扰反馈、不过度游戏化

---

## 1. 版本背景

当前版本已经具备完整的舒尔特方格训练闭环：

```text
选择训练规格和年龄段 → 开始训练 → 按顺序点击数字 → 完成后查看成绩结果 → 再来一次
```

但现有结果页主要展示单次训练结果，用户完成训练后只能看到本次耗时、错误次数和成绩等级，缺少与历史表现之间的对比。用户很难知道：

1. 本次是否比上次更好。
2. 是否刷新了自己的最佳成绩。
3. 最近训练表现是否稳定。
4. 下一次训练应该重点提升速度还是准确率。

因此 V0.4 新增「训练记录」能力：每次用户完成训练后，自动保存训练记录，并在结果页提示用户本次表现是否有所提升，从而让用户形成更明确的训练反馈闭环，提高持续训练意愿。

---

## 2. 版本目标

### 2.1 核心目标

将原有单次训练结果升级为「可持续追踪的训练反馈闭环」：

```text
完成训练 → 自动保存记录 → 对比历史表现 → 生成进步提示 → 给出下一次目标 → 引导继续训练
```

### 2.2 产品目标

1. 让用户每次训练后都能看到「本次表现是否提升」。
2. 让训练结果从单次反馈升级为持续反馈。
3. 通过正向、克制、可执行的总结文案提高用户复练意愿。
4. 为后续趋势图、训练计划、AI 个性化分析提供数据基础。

### 2.3 体验目标

1. 不增加训练过程中的干扰。
2. 不强制用户查看历史数据。
3. 结果页优先展示本次结果，其次展示进步提示。
4. 历史记录入口轻量、清晰，不做复杂排行榜或社交比较。
5. 所有训练记录默认保存在本地设备，不依赖登录。

## 4. 核心用户流程更新

### 4.1 完整训练流程

```text
打开 App
  ↓
进入首页 / 训练配置页
  ↓
选择方格规格、年龄段、训练模式
  ↓
点击「开始训练」
  ↓
进入训练页
  ↓
完成全部数字点击
  ↓
系统停止计时
  ↓
生成本次训练结果
  ↓
自动保存训练记录
  ↓
读取同条件历史记录
  ↓
计算本次是否提升
  ↓
展示训练报告、进步提示、下一次目标
  ↓
再来一次 / 查看记录 / 返回首页 / AI 分析
```

### 4.2 首次训练流程

首次训练没有可对比历史记录，结果页应提示：

```text
这是你的首次 5×5 标准训练，后续完成训练后将展示进步趋势。
```

### 4.3 非首次训练流程

非首次训练完成后，系统需要优先与「同规格 + 同年龄段 + 同训练模式」下的上一条有效记录进行对比，并补充展示是否刷新最佳成绩。

## 5. 训练记录保存需求

### 5.1 保存触发时机

训练记录只在用户完整完成一局训练后保存。

| 场景             | 是否保存 | 说明              |
|----------------|-----:|-----------------|
| 正常完成训练         |    是 | 点击最后一个正确数字后保存   |
| 中途退出训练         |    否 | 未完成，不保存为正式记录    |
| 点击重新开始         |    否 | 原局作废，不保存        |
| App 进入后台后恢复并完成 |    是 | 如果训练状态仍有效，完成后保存 |
| App 被系统杀死      |    否 | 当前版本不做恢复保存      |
| 辅助模式完成训练       |    是 | 保存但标记为辅助模式      |

### 5.2 保存内容

每条训练记录至少包含以下字段：

| 字段                | 类型                | 说明              |
|-------------------|-------------------|-----------------|
| id                | String            | 记录唯一 ID         |
| createdAt         | Long              | 训练完成时间戳         |
| gridSize          | Int               | 方格规格，例如 3、4、5、7 |
| ageGroup          | AgeGroup          | 年龄段             |
| trainingMode      | TrainingMode      | 标准模式 / 辅助模式     |
| elapsedTimeMillis | Long              | 完成耗时            |
| errorCount        | Int               | 错误次数            |
| scoreLevel        | ScoreLevel        | 成绩等级            |
| isPersonalBest    | Boolean           | 是否刷新当前条件下最佳成绩   |
| previousRecordId  | String?           | 用于对比的上一条记录 ID   |
| improvementStatus | ImprovementStatus | 提升、稳定、波动、首次记录等  |
| timeDeltaMillis   | Long?             | 与上一条记录的耗时差值     |
| errorDelta        | Int?              | 与上一条记录的错误次数差值   |

### 5.3 记录有效性

1. 只有完成所有数字点击的记录才算有效记录。
2. 标准模式和辅助模式必须分开统计。
3. 不同方格规格不互相比较。
4. 不同年龄段不互相比较。
5. 当前版本不允许用户手动编辑训练记录。
6. 删除记录只通过「清空全部训练记录」完成，暂不支持单条删除。

## 6. 进步判断规则

### 6.1 对比范围

进步对比必须基于相同训练条件：

```text
方格规格 + 年龄段 + 训练模式
```

示例：

```text
本次：5×5 / 18岁以上 / 标准模式
对比对象：上一条 5×5 / 18岁以上 / 标准模式记录
```

不应将 5×5 与 7×7 对比，也不应将标准模式与辅助模式直接对比。

### 6.2 对比基准

本期支持三个对比基准：

| 基准    | 说明                   | 展示优先级 |
|-------|----------------------|------:|
| 上一次记录 | 与最近一次同条件训练对比         |     高 |
| 历史最佳  | 判断是否刷新个人最佳           |     高 |
| 最近平均  | 最近 5 次同条件训练平均耗时和平均错误 |     中 |

### 6.3 判断指标

成绩等级仍然主要基于完成时间。错误次数作为辅助指标展示，不直接改变成绩等级。

进步判断建议使用「完成时间 + 错误次数」综合判断：

1. 如果完成时间明显减少，判断为速度提升。
2. 如果完成时间接近但错误次数减少，判断为稳定性提升。
3. 如果完成时间减少但错误次数增加，判断为速度提升但准确性波动。
4. 如果完成时间增加且错误次数增加，判断为表现波动。
5. 如果完成时间和错误次数变化很小，判断为表现稳定。

### 6.4 时间变化阈值

为避免 0.01 秒级别的微小变化造成误导，建议设置最小有效提升阈值：

```kotlin
val minEffectiveDeltaMillis = maxOf(300L, (previousElapsedTimeMillis * 0.01).toLong())
```

也就是说，只有当耗时变化超过 300ms 或超过上次耗时的 1% 时，才认为是有效变化。

### 6.5 ImprovementStatus 定义

```kotlin
enum class ImprovementStatus {
    FIRST_RECORD,        // 首次记录，暂无对比
    IMPROVED_SPEED,      // 速度提升
    IMPROVED_ACCURACY,   // 错误减少，稳定性提升
    PERSONAL_BEST,       // 刷新个人最佳
    STABLE,              // 表现稳定
    MIXED,               // 速度和准确性表现不一致
    DECLINED             // 表现波动或下降
}
```

### 6.6 判断示例

| 本次表现       | 对比上次       | 判断结果  | 文案方向                 |
|------------|------------|-------|----------------------|
| 更快，错误相同或更少 | 时间减少，错误不增加 | 速度提升  | 「比上次快了 1.2 秒」        |
| 时间接近，错误更少  | 时间变化小，错误减少 | 稳定性提升 | 「速度稳定，错误更少」          |
| 更快，但错误更多   | 时间减少，错误增加  | 混合表现  | 「速度更快，但准确性略有波动」      |
| 更慢，错误更多    | 时间增加，错误增加  | 表现波动  | 「本次略有波动，建议先稳住准确率」    |
| 快于历史最佳     | 创新低耗时      | 刷新最佳  | 「刷新了你的 5×5 标准模式最佳成绩」 |

## 7. 训练总结优化需求

### 7.1 原结果总结问题

原结果页只展示本次完成时间、错误次数、方格规格、年龄段和成绩等级。用户可以知道「这次结果是多少」，但不知道「这次相比过去是否更好」。

### 7.2 新总结结构

结果页总结建议调整为四层：

```text
本次结果 → 进步提示 → 表现解释 → 下一次目标
```

### 7.3 结果页总结内容

结果页需要新增「表现总结卡片」，展示以下内容：

1. 本次整体表现。
2. 与上一次相比是否提升。
3. 是否刷新个人最佳。
4. 错误次数变化。
5. 下一次训练建议目标。

### 7.4 总结文案规则

文案需要满足以下要求：

1. 简短、直接、克制。
2. 优先给出正向反馈。
3. 不使用夸张游戏化话术。
4. 不使用医疗承诺。
5. 不说「治疗注意力问题」「提升智商」等表达。
6. 即使表现下降，也应给出可执行建议。

### 7.5 总结文案示例

#### 首次记录

```text
这是你的首次 5×5 标准训练，完成时间为 18.42 秒。继续完成几次训练后，这里会展示你的进步趋势。
```

#### 速度提升

```text
本次比上次快了 1.26 秒，错误次数保持不变，视觉搜索速度有所提升。
```

#### 准确率提升

```text
本次速度基本稳定，但错误次数减少了 1 次，说明点击准确性有所提升。
```

#### 刷新最佳

```text
你刷新了 5×5 标准模式的个人最佳成绩，比历史最佳快了 0.84 秒。
```

#### 速度提升但错误增加

```text
本次完成时间更快，但错误次数增加了 1 次。下一次建议先保持准确率，再继续提速。
```

#### 表现波动

```text
本次表现略有波动。建议下一轮放慢一点节奏，先保证目标数字切换准确。
```

### 7.6 下一次目标生成规则

下一次目标必须可执行，避免过度激进。

| 当前状态   | 下一次目标                  |
|--------|------------------------|
| 首次记录   | 再完成 1 次同规格训练，建立对比基准    |
| 速度提升   | 尝试保持当前节奏，错误次数不增加       |
| 准确率提升  | 尝试在保持 0 错误或低错误的前提下略微提速 |
| 刷新最佳   | 尝试稳定在当前最佳成绩附近          |
| 表现波动   | 优先降低错误次数，不急于提速         |
| 连续多次优秀 | 可以尝试更高规格或更严格目标         |

## 9. AI 分析能力更新

### 9.1 AI 分析输入更新

当用户点击「生成 AI 分析」时，除本次训练结果外，可以附带最近训练摘要。

建议传入内容：

1. 本次训练记录。
2. 同条件上一条训练记录。
3. 同条件历史最佳记录。
4. 最近 5 次同条件训练摘要。
5. 系统生成的基础进步判断。

### 9.2 AI 分析输出方向

AI 分析不再只分析单次结果，而是结合历史表现给出建议：

1. 本次表现总结。
2. 与上次相比的变化。
3. 最近训练稳定性。
4. 速度和错误之间的平衡建议。
5. 下一次训练目标。

### 9.3 降级规则

即使用户未配置 AI，也必须展示基础总结、进步提示和下一次目标。

AI 只作为增强分析，不作为训练记录和基础总结的必要条件。

## 10. 数据结构建议

### 10.1 TrainingRecord

```kotlin
data class TrainingRecord(
    val id: String,
    val createdAt: Long,
    val gridSize: Int,
    val ageGroup: AgeGroup,
    val trainingMode: TrainingMode,
    val elapsedTimeMillis: Long,
    val errorCount: Int,
```

## 11. 本地存储需求

### 11.1 存储方式建议

当前版本建议使用本地数据库保存训练记录。

KMP 项目可考虑：

1. SQLDelight：适合 Kotlin Multiplatform 数据持久化。
2. Room KMP：如果项目已经使用 AndroidX Room KMP，可考虑统一使用。
3. 简化版本可先使用本地文件或 key-value 存储，但不建议长期使用。

### 11.2 存储限制

1. 默认最多保存最近 1000 条训练记录。
2. 超过上限后自动删除最早记录。
3. 清空记录需要用户二次确认。
4. 不保存用户身份信息。
5. 不做云同步。

### 11.3 隐私说明

设置页需要展示：

```text
训练记录仅保存在本地设备。
AI 分析仅在你点击生成时使用本次报告和最近训练摘要。
你可以随时清空本地训练记录。
```

## 12. 异常与边界场景

| 场景           | 处理方式                |
|--------------|---------------------|
| 首次训练完成       | 保存记录，显示首次记录提示       |
| 没有同条件历史记录    | 不跨规格对比，提示暂无同条件对比    |
| 有其他规格记录      | 不用于本次进步判断           |
| 辅助模式记录       | 单独保存和统计，不参与标准模式最佳成绩 |
| 保存失败         | 结果页展示本次结果，并提示记录保存失败 |
| 清空记录后完成训练    | 按首次训练处理             |
| 最近记录数量少于 5 条 | 最近平均基于已有记录计算        |
| 时间差小于阈值      | 判断为表现稳定             |
| 完成时间更快但错误更多  | 判断为混合表现，提示平衡速度与准确率  |

## 14. 验收标准

### 14.1 训练记录保存验收

- 用户完成训练后，系统自动保存一条训练记录。
- 中途退出或重新开始不会保存记录。
- 训练记录包含规格、年龄段、训练模式、完成时间、错误次数和成绩等级。
- 标准模式和辅助模式记录分开保存。
- 清空本地记录后，历史记录页为空。

### 14.2 进步提示验收

- 首次训练后展示首次记录提示。
- 非首次同条件训练后展示与上一次相比的变化。
- 完成时间明显减少时展示速度提升提示。
- 错误次数减少时展示准确性提升提示。
- 刷新最佳成绩时展示个人最佳提示。
- 表现波动时给出温和、可执行的训练建议。

### 14.3 结果页总结验收

- 结果页优先展示完成时间和成绩等级。
- 结果页展示进步提示卡片。
- 结果页展示下一次训练目标。
- 未配置 AI 时，基础总结仍然可用。
- 配置 AI 后，可以基于本次记录和历史摘要生成增强分析。

### 14.4 历史记录页验收

- 用户可以从首页或结果页进入训练记录页。
- 记录列表按完成时间倒序展示。
- 支持按规格、训练模式、时间范围筛选。
- 无记录时展示空状态。
- 记录中能看到完成时间、错误次数、成绩等级和对比提示。

### 14.5 数据管理验收

- 设置页展示本地训练记录数量。
- 用户可以清空全部训练记录。
- 清空前必须二次确认。
- 清空后首页、结果页和记录页状态正确刷新。

## 15. 版本结论

V0.4 的核心不是增加复杂功能，而是把「训练完成后的反馈」从一次性结果升级为持续性的进步反馈。

新的训练闭环应为：

```text
训练 → 保存记录 → 对比历史 → 看到进步 → 获得下一次目标 → 继续训练
```

通过训练记录、进步提示、历史最佳和下一次目标，用户能够更清楚地感知自己的变化，从而提升继续训练的动力。AI 分析仍然保持为可选增强能力；即使不配置 AI，基础报告和进步反馈也必须完整可用。
